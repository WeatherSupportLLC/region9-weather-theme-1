# Region 9 Live Studio 17.1.0 staging checklist

Record operator, timestamp, result, and evidence for every item. Stop on unexplained data loss, PHP fatal errors, failed migration, public draft exposure, or scheduler duplication.

## Install

- [ ] Put staging behind an appropriate maintenance/access-control boundary.
- [ ] Back up the staging database, uploads, active plugin directory, active child-theme directory, and current ZIP artifacts.
- [ ] Record current plugin/theme versions, active GeneratePress parent version, GP Premium version, scheduler next run, latest publication, and public cache configuration.
- [ ] Upload `region9-live-studio-17.1.0.zip` and replace the installed `region9-live-studio` plugin.
- [ ] Reactivate the plugin if the installer deactivated it; confirm one scheduler event and migration `17.1.0`.
- [ ] Upload `region9-weather-theme-17.1.0.zip` and replace the exact existing child-theme folder shown in its manifest.
- [ ] Confirm **Region 9 Weather Studio - GeneratePress Child** remains active with `Template: generatepress`.
- [ ] Confirm GeneratePress and GP Premium compatibility and retained Customizer settings, menus, and widgets.

## Functional

- [ ] Run manual validation and confirm success.
- [ ] Confirm workspace rows populate once per enabled canonical product.
- [ ] Confirm generation duration displays, including `0.000s` when appropriate.
- [ ] Confirm Decision History receives the validation record.
- [ ] Approve a designated test product and verify no automatic publication occurs.
- [ ] Publish the approved test product and verify its public page/homepage data updates.
- [ ] Confirm unrelated products and caches remain unchanged.
- [ ] Roll back the test product from Publication History and verify the prior snapshot and new rollback event.
- [ ] Confirm rejected and pending drafts remain absent from REST and public theme output.
- [ ] Test zero-alert and active-alert Alert Center states, counties, instructions, expiration, and source health.
- [ ] Test prominent radar/full-radar navigation and fallback behavior.
- [ ] Test outage no-data, informational, stale/unavailable, configured-provider, and full-page navigation states.
- [ ] Open every Region 9 Studio submenu and confirm the dedicated dashboard, capability checks, and actions.

## Visual

- [ ] Desktop homepage: radar prominence, two columns, sidebar alignment, graphics/discussions, no broken images.
- [ ] Tablet homepage: stacked/compact grid, readable radar, no horizontal overflow.
- [ ] Mobile homepage: alert/risk/radar/conditions/forecast/outage/operations/resources order.
- [ ] Right sidebar: Alert Center, Weather Operations, outage/risk/confidence/resources are visually distinct.
- [ ] Forecast image/discussion panels include professional no-data states.
- [ ] Admin tables scroll safely on narrow screens and controls remain keyboard accessible.
- [ ] No generic placeholder admin pages, clipped maps, empty white boxes, or broken image icons.

## Soak

- [ ] Observe scheduler and sources for 24–48 hours.
- [ ] Confirm no duplicate cron event, overlapping run, stale lock, or unexpected automatic publication.
- [ ] Review source health transitions, retry counts, latency, stale fallback, and upstream outages.
- [ ] Review audit history and current errors after each scheduled cycle.
- [ ] Record runtime, generation duration, peak memory, and process/object-cache behavior; confirm no degradation trend.
- [ ] Obtain operational owner sign-off before production deployment.
