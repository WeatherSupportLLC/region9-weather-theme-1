## Executive findings

The RC1 tree has two regression clusters:

1. **Public homepage and sidebar composition was flattened.** The homepage is a single include that places Decision Impact and Current Conditions before radar, renders radar as the last major section, does not render a right sidebar/widget rail, and has no Power Outage Tracker section. Forecast pages do preserve a forecast sidebar fallback, but the dedicated homepage/right-sidebar and Alert Center sidebar compositions are not represented as reusable templates.
2. **Forecast Production/admin workflows are structurally present but not operationally wired.** Validation calls `refresh_workspace_from_decision()`, yet the admin page is one monolithic renderer for all submenus, batch controls are disabled, publication actions only update `r9ls_last_publish`, and the product generator does not promote workspace approvals into the canonical approved publication state. This explains empty workspace/duration/history symptoms when validation produces no material-change queue or when operators use the disabled Forecast Production controls.

## Theme audit

### Homepage structure

- `front-page.php` delegates directly to `template-parts-studio-home.php` and does not define a two-column operational shell or sidebar region.
- `template-parts-studio-home.php` currently orders homepage content as emergency mode, optional live broadcast, Decision Impact Dashboard + Current Conditions, Severe Weather Risk Guide + Weather Operations, forecast cards, social hub, then radar.
- The reference behavior requires live radar/map to be the primary homepage feature. In RC1 radar is last, lazy-loaded, and visually secondary.
- Power Outage Tracker is absent from homepage markup and appears only as a registered/public page slug in existing validation expectations.
- Weather Operations exists as a compact panel, but it is not a sidebar rail. The right sidebar and Alert Center sidebar are not part of the homepage layout.

### GeneratePress compatibility

- `style.css` remains a GeneratePress child theme stylesheet and `functions.php` enqueues the parent `generatepress-parent` stylesheet.
- Theme setup registers menus and standard WordPress supports without overriding GeneratePress templates globally.
- Compatibility risk is low if repairs remain in child-theme templates, template parts, sidebars, and CSS.

### Widgets, menus, and pages

- Five sidebars are registered: live, forecast, alert, and two footer columns.
- There is no `sidebar.php` in the tree, so classic `get_sidebar()` compatibility and a reusable right-sidebar fallback are missing.
- Existing validation scripts expect public slugs including `outage-tracker`, `radar`, `alerts`, `storm-timing`, `threat-breakdown`, and operations/protection pages.

## Plugin audit

### Bootstrap/scheduler/validation

- The plugin bootstrap loads scheduler, validation/rule, material-change, product-generator, REST, and admin classes.
- Scheduler activation schedules `r9ls_validate_weather_operations`; manual/scheduled validation updates `r9ls_current_products`, detects material changes, and calls `R9LS_Product_Generator::refresh_workspace_from_decision()`.
- Root cause for workspace emptiness is likely not lack of a scheduler call but mismatch between admin display/action expectations and the workspace option lifecycle, plus reliance on material-change queue actions for approvals.

### Forecast Production and publication

- `R9LS_Product_Generator::refresh_workspace_from_decision()` builds private pending-review products and stores `r9ls_forecast_production_workspace` plus `r9ls_product_generation_last` duration.
- `generate_from_approved_state()` publishes canonical products, appends product history, invalidates caches, and also populates workspace, but it reads approved state rather than approved workspace rows.
- `R9LS_Material_Change_Engine::publish()` only writes `r9ls_last_publish`; it does not update `R9LS_Product_Generator::STATE`, call the generator, or transition product publication states.
- Admin batch buttons are disabled, so operators cannot progress generated products through approval/publication from the Forecast Production workspace.

### Decision History

- Decision history is stored only when `Material_Change_Engine::decide()` is called on queue items.
- Workspace generation itself does not append decision history entries. If validation has no queued material changes or the operator uses disabled workspace controls, Decision History remains empty.

### Alert Center

- Public legacy Alert Center functionality is primarily in the theme REST route and `assets/js/studio.js`.
- Plugin canonical alert state is exposed through `region9-live-studio/v1/alerts` but admin Alert Center submenu renders the same monolithic dashboard as every other submenu.
- Alert Center sidebar composition is missing as a dedicated template/sidebar renderer.

### Admin dashboards/menus

- `R9LS_Admin::menu()` registers multiple submenus, but every submenu callback is `page()` and the method does not branch by `$_GET['page']`.
- This causes duplicated/incomplete pages: Forecast Production, Forecast Products, Approval Queue, Decision History, Publication History, Alert Center, Source Health, Scheduler Health, Overrides, System Health, and Backup & Protection all display the same dashboard.
