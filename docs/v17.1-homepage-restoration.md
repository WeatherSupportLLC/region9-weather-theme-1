# v17.1 Homepage Restoration

## Previous regression

The RC1 homepage had drifted away from the familiar Region 9 Weather operations layout. Radar was rendered after several other sections, the homepage had no true right sidebar, the Power Outage Tracker was absent from the homepage, and Alert Center / Weather Operations appeared only as generic or embedded content instead of persistent operational sidebar modules.

## Restored homepage structure

The v17.1 homepage restores a polished two-column operational layout while keeping the existing GeneratePress child theme, header, navigation, branding, footer, Customizer settings, public URLs, and modern RC visual styling.

Main content column:

1. Optional emergency mode banner and optional live broadcast remain above the operations layout when enabled.
2. Prominent live Region 9 radar/map appears as the first primary operational module.
3. Decision Impact Dashboard follows radar.
4. Current Conditions remains available with the existing city slider hooks.
5. Weather Headlines and Forecast Confidence are presented as paired status cards.
6. Today’s Forecast and Seven-Day Forecast use restored graphic-plus-discussion layouts.
7. Severe Weather Risk guide and Power Outage Tracker appear as operational modules.
8. Existing social media section remains available when enabled.

Right sidebar:

1. Alert Center module.
2. Weather Operations navigation.
3. Power Outage Tracker compact module.
4. Current Region 9 risk and Forecast Confidence module.
5. Emergency Resources links.

## Component map

| Component | Implementation |
|---|---|
| Live radar/map | `template-parts-studio-home.php` uses the existing `r9_setting('radar_url', ...)` behavior and preserves the full `/radar/` page link. |
| Alert Center sidebar | `r9_home_alert_sidebar_module()` reads only the normalized canonical alert state when available and falls back to an all-clear/unavailable public message. |
| Weather Operations sidebar | `r9_home_operations_sidebar_module()` links to forecast, hazards, radar, Alert Center, travel, agriculture, protection, and rural operations pages. |
| Power Outage Tracker | `r9_home_outage_module()` renders approved/configured state only, never fabricates outage counts, and links to the full outage page. |
| Risk and confidence | `r9_home_risk_sidebar_module()` combines current theme risk with the approved Forecast Confidence product when available. |
| Forecast graphics/discussions | `r9_home_forecast_module()` supports approved product graphics or branded placeholders, discussion text, risk, confidence, timing, affected counties, and update timestamps. |
| Sidebar fallback | `r9_home_sidebar_fallback()` and `sidebar.php` ensure useful modules render even when no widgets are assigned. |

## Responsive behavior

Desktop uses a two-column grid with a sticky, visually distinct right sidebar. Mobile stacks priority modules in the required order: alerts, current risk, live radar, current conditions, forecast content, outage tracker, Weather Operations, related products, and emergency resources. CSS media queries collapse grids to one column, constrain iframe width, and prevent horizontal scrolling or clipped maps.

## Fallback behavior

- Radar includes a branded fallback layer and full radar page link if the iframe fails to display.
- Outage Tracker supports informational, no-outage, stale, and unavailable states through existing theme settings without making render-time HTTP calls.
- Alert Center supports no active alerts, stale/unavailable status, and normalized alert summaries without exposing raw payloads.
- Forecast modules show professional no-data language and branded media placeholders when no approved Live Studio product or uploaded graphic exists.
- Sidebar modules render even when widget areas are empty.

## Data sources used

The homepage uses only existing local WordPress state, theme mods, approved Live Studio public product helpers, and the canonical normalized alert state helper when available. It does not introduce new external feeds, new production-only URLs, or unverified business logic.

## Safety and performance guardrails

- No render-time PHP HTTP calls were added to the homepage or sidebar templates.
- Existing public REST consumers and JavaScript hooks are preserved.
- GeneratePress parent declaration and parent stylesheet enqueue are preserved.
- Public URLs and menu/page slugs remain unchanged.
- ZIP-based reference verification remains limited by the unavailable v15/v15.1 and RC1 reference packages noted in the Milestone 1 audit.
