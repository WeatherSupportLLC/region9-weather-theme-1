# Region 9 Live Studio 17.1.0 administrative experience

## Administrative ownership

When Region 9 Live Studio is active, the plugin owns one `Region 9 Studio` top-level menu and every operational submenu. The GeneratePress child theme removes its legacy top-level entry and does not register duplicate callbacks beneath the plugin. Its legacy administration remains available only when the plugin is inactive.

Each submenu is registered to a named callback rather than the former generic page dispatcher. The menu includes Automation, Forecast Production, Forecast Products, Approval Queue, Decision Dashboard, Decision History, Publication History, Alert Center, Source Health, Scheduler Health, Audit Log, Theme Site Setup, Theme System Health, Backup & Restore, Live Controls, Partners, Clients, Production, Rural Operations, Rural Reports, Protection, System Health, and Backup & Protection.

## Automation and production

The Automation dashboard summarizes validation, generation, approval, publication, alert refresh, source refresh, scheduler, queue, and workspace state. The progress indicator deliberately stops before publication until an approved product is explicitly published.

Forecast Production retains the 17.1 authoritative private workspace. It provides isolated Approve, Reject, and Publish controls; batch approval, rejection, and publication; expandable grouped changes; product previews; source/publication references; and direct navigation to Decision Dashboard, Decision History, and Publication History. Theme integration status is presented alongside the workspace. Rollback remains attached to immutable publication-history restore points.

## Alert Center

Alert Center reads only `r9ls_canonical_alert_state`. It summarizes active alerts, watches, warnings, advisories, affected counties, alert health, source health, refresh state, and last update. Its normalized table and timeline show approved canonical fields such as event, severity, counties, effective/expiration times, headline, and instruction. Raw provider payloads are never rendered.

## Source and scheduler health

Source Health presents NWS, SPC, WPC, MRMS, Radar, Grid Forecast, and Hourly Forecast. Missing integrations display `Unavailable`; the dashboard does not invent telemetry. For integrated sources, the national-guidance engine now retains last success, last failure, response latency, cached age, retry status, and consecutive error count.

Scheduler Health presents the last validation, generation, and publication, next validation and cron run, cron and running state, queue count, scheduler health, and bounded failure history. It reads the existing lock and scheduler options without triggering external requests.

## Theme Site Setup and system health

Theme Site Setup checks GeneratePress, GP Premium detection, theme/plugin/migration versions, required public pages, primary navigation, operational widgets/fallbacks, shortcodes, REST inventory, scheduler, Alert Center, and forecast-page readiness. Its protected repair action reruns the idempotent migration, repairs defaults, and ensures the scheduler event exists; it does not fabricate pages or weather data.

Theme System Health reports PHP, WordPress, memory, cron, REST availability, filesystem writes, uploads, plugin compatibility, theme integration, warnings, current errors, and recovery suggestions. The broader System Health screen combines platform and source health.

## Backup and protection

Backup & Restore exports an allowlisted JSON document containing configuration, live controls, workspace state, canonical published products, decision/publication histories, overrides, and canonical alert state. Import is capability- and nonce-protected, limited to 5 MB, validates the Region 9 backup schema, updates only allowlisted options, and reruns the idempotent migration. Publication-history records remain available as product-level rollback shortcuts.

Backup & Protection combines backup controls with publication-lock, automatic-publication, current-error, and migration state.

## Live Controls

The protected Live Controls form manages Emergency Mode, Banner, Ticker, Broadcast, Homepage Hero mode, Radar mode, Alert override, Maintenance Mode, Publication Lock, and override expiration in `r9ls_live_controls`. Values are sanitized, actor/time stamped, and audited. These controls do not directly publish private forecast drafts.

## Operations pages

Partners, Clients, Production, Rural Operations, Rural Reports, and Protection are dedicated operational views. Each reports relevant workspace/public/alert state and links to its responsible management surfaces rather than presenting placeholder copy or inventing partner/client records.

## Visual and accessibility behavior

All screens share responsive status cards, health badges, progress indicators, tables, detail disclosures, and control grids. Tables become horizontally scrollable on narrow WordPress admin screens; card/control grids collapse to one column. Native headings, tables, labels, links, buttons, checkboxes, details, and progress elements preserve keyboard operation and semantic structure.

## Security and data boundaries

- Every renderer and mutation requires `manage_options`.
- Every mutation requires a dedicated WordPress nonce.
- Product actions continue to sanitize and validate canonical product IDs.
- Alert Center and public product views use normalized/canonical records only.
- Dashboard rendering performs no external HTTP requests.
- Backup imports update only the explicit Region 9 option allowlist.
- The public REST boundary remains approved-and-published only.

## Validation

Run `php scripts/validate-v17.1-admin.php`. The validator checks authoritative menu ownership, dedicated callbacks/renderers, Alert Center, source and scheduler health, automation, production controls, theme setup and health, backup, live controls, REST boundaries, nonce/capability enforcement, and responsive admin styling.
