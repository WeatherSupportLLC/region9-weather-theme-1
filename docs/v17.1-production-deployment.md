# Region 9 Live Studio 17.1.0 production deployment

## Maintenance window and prerequisites

Schedule a staffed maintenance window after staging completes the 24–48 hour soak. Have WordPress, hosting/cache, database, and Region 9 operations owners available. Download and verify both ZIPs, both manifests, `SHA256SUMS.txt`, certification reports, staging evidence, and rollback artifacts before starting.

## Exact deployment order

1. Announce the maintenance window and pause editorial publication activity.
2. Record scheduler state, latest public product references, active theme/plugin folders, and cache configuration.
3. Back up the database, uploads, `region9-live-studio` directory, exact active child-theme directory, theme mods, menus/widgets, and server configuration. Verify restore access.
4. Enable maintenance mode or otherwise prevent concurrent admin changes; do not modify `wp-config.php`.
5. Verify artifact hashes with `sha256sum -c SHA256SUMS.txt`.
6. Update/replace the **Region 9 Live Studio plugin first** with `region9-live-studio-17.1.0.zip`.
7. Activate/reactivate the plugin and verify migration `17.1.0`, preserved options/histories, one cron event, no fatal errors, and automatic publication still disabled unless intentionally configured.
8. Update/replace the **existing GeneratePress child-theme folder second** with `region9-weather-theme-17.1.0.zip`. Do not install it under a new slug.
9. Confirm the child theme remains active, parent is GeneratePress, GP Premium remains compatible, and Customizer/menu/widget assignments remain intact.
10. Clear the plugin aggregate/product transients and authorized WordPress/page/object/CDN caches. Do not delete publication or workspace options.
11. Run a manual validation; verify workspace rows, generation duration, Decision History, scheduler health, source health, and Alert Center.
12. Approve and publish only the preselected smoke-test product; verify REST/public output and then perform product rollback if the deployment plan requires a rollback rehearsal.
13. Smoke-test desktop/tablet/mobile homepage, radar, right sidebar, outage module, forecast graphics/discussions, public forecast pages, and every admin dashboard.
14. Disable maintenance mode, resume editorial activity, announce completion, and begin heightened monitoring.

## Rollback triggers

Rollback immediately for PHP fatal errors, failed/non-idempotent migration, missing canonical products/history, public draft or rejected-product exposure, broken GeneratePress relationship, repeated scheduler events, inability to validate/approve/publish safely, widespread homepage/admin failure, or material performance/memory regression. Upstream source unavailability alone is not a code rollback trigger when stale/unavailable states behave correctly.

## Post-deployment monitoring

Monitor scheduler runs, source health, alert normalization, audit/current errors, generation/runtime/memory, publication actions, caches, and public rendering throughout the maintenance period and for at least 24 hours afterward.
