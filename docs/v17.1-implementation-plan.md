# v17.1 Implementation Plan

This plan prepares implementation without changing runtime behavior in the audit commit. It intentionally avoids release packaging, build-script repair, and release metadata updates.

## Phase 0: Reference extraction gate

1. Obtain the three requested ZIP artifacts in the workspace without committing them.
2. Extract each artifact to an ignored temporary directory, for example `/tmp/r9-v17.1-reference/`.
3. Capture file inventories and targeted diffs for the audited files.
4. Update the parity matrix rows marked **ZIP verification required** with exact v15/v15.1 and RC1 artifact filenames/classes before code changes.

## Phase 1: Homepage/public surface repair

1. Rebuild `front-page.php` as an explicit GeneratePress-child-safe homepage shell.
2. Refactor `template-parts-studio-home.php` into ordered modules:
   - emergency banner/live broadcast when enabled;
   - primary live radar/map hero;
   - right sidebar rail;
   - Power Outage Tracker;
   - Alert Center sidebar module;
   - Weather Operations sidebar module;
   - Decision Impact Dashboard;
   - forecast graphics/cards;
   - social/footer sections.
3. Add `sidebar.php` with Region 9 operational fallback widgets while preserving registered widget areas.
4. Add slug-aware sidebar behavior in `page.php` for alert pages versus forecast pages.
5. Keep GeneratePress parent enqueue, child stylesheet header, menus, and supports intact.

## Phase 2: Forecast Production workflow repair

1. Split `R9LS_Admin::page()` into dedicated render methods for each submenu.
2. Build a Forecast Production page that reads `R9LS_Product_Generator::WORKSPACE`, displays generated rows, and enables nonce-protected approve/reject/publish/rollback actions.
3. Add product-generator methods to:
   - promote approved workspace products into `R9LS_Product_Generator::STATE`;
   - publish approved rows into `R9LS_Product_Generator::PRODUCTS`;
   - append product history and decision history consistently;
   - invalidate REST/public caches.
4. Update material-change publishing so it drives canonical product publication rather than only writing `r9ls_last_publish`.
5. Display generation duration from workspace/generator/scheduler fallback in that order.

## Phase 3: Alert Center and dashboards

1. Add dedicated admin renderers for Alert Center, Source Health, Scheduler Health, Decision History, Publication History, Overrides, System Health, and Backup & Protection.
2. Make Alert Center read canonical plugin alert state and preserve the existing public theme alert REST fallback.
3. Remove duplicate generic-dashboard rendering from submenu pages while keeping the top-level dashboard summary.

## Phase 4: Regression tests

Add or update tests without repairing packaging scripts:

- Homepage template order test: radar/map before dashboards and forecast sections.
- Sidebar test: homepage right rail, alert sidebar, Weather Operations module, and outage tracker links.
- Forecast workspace test: manual validation creates non-empty workspace rows and numeric duration.
- Workflow test: approve/publish transitions product to public REST visibility.
- Decision history test: workspace decisions append entries.
- Admin menu test: every registered submenu has a unique render path.
- GeneratePress compatibility test: parent enqueue and `Template: generatepress` remain intact.

## Phase 5: Manual verification

If a runnable WordPress harness is available:

1. Activate GeneratePress parent, Region 9 child theme, and Region 9 Live Studio plugin.
2. Capture screenshots for homepage, Alert Center, Forecast Production, and Decision History after a manual validation run.
3. Verify no ZIP artifacts or extracted reference directories are staged.
